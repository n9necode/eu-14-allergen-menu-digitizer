## 1. EXECUTIVE SUMMARY

Built a production-ready Apify Actor that ingests restaurant menu images/PDFs and returns structured JSON per dish: dish names (translated), prices, atomic ingredients, EU-14 allergen tags with confidence scores, dietary classification (vegan/vegetarian/pescetarian/other), nutrition estimates, and a confidence/review flag.

Runs on a **bring-your-own Gemini API key** — the end user supplies the key, so the actor owner pays $0 for AI inference.

**Moat:** schema quality + vertical-specific allergen keyword maps (Italian, Indian, Japanese, Mexican, general), not price.

## 7. HOW TO RUN / DEPLOY

### Local (no Apify account needed)
```bash
cd C:\Users\newleaf888\Documents\eu-14-allergen-menu-digitizer
npm install
# Create INPUT.json per input_schema.json, including your Gemini key
npm start               # writes OUTPUT.json via filesystem shim
npm test                # runs the 15 unit tests
npm run lint            # syntax check
```

### Apify Platform
1. Create a new Actor; paste this repo as source.
2. Set runtime to Node 16+ (Apify actor-node-16-chrome or newer).
3. For PDF rendering, add `poppler-utils` (`pdftoppm`) in the Dockerfile; if absent, the Actor sends the whole PDF document to Gemini directly (fallback already implemented).
4. Users supply `geminiApiKey` at runtime (marked `secret` in `input_schema.json`).
5. Build & run; results appear in the Apify dataset.
